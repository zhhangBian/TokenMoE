\section{Design}

\subsection{Admission requests}

Each workload record represents one real LLM admission before target
generation. It contains a prompt, typed character spans, source-group
provenance, and \AgentMeta. For agent trajectories, a record includes only
events that preceded the target action. This prevents output-to-input leakage.

\subsection{Route signatures}

For metadata key $m$ and MoE layer $l$, \RouteSig maintains a conditional
distribution $P(e \mid m,l)$ over logical expert IDs. Keys fall back from
agent-, role-, phase-, tool-, block-, and position-specific tuples to a global
distribution. Additive smoothing handles sparse keys, while support,
concentration, and recent active-set stability determine confidence.

The evaluated predictors share one per-segment, per-layer interface. Global
frequency tests long-run popularity. A bounded temporal window tests recent
routing locality. \RouteSig tests the incremental metadata hypothesis. Expert
budgets are multiples of the model router's top-$k$.

\subsection{Correctness boundary}

Tracing is read-only. Selected expert IDs and weights are copied after native
top-$k$ selection; model execution consumes the original tensors. Missing
scores are explicit rather than fabricated. New models and parallel layouts
require token-alignment checks and capture-on/off generated-token equivalence.
