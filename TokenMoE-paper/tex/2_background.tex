\section{Background and Motivation}

\subsection{Late expert knowledge}

At each sparse layer, the router maps a token representation to top-$k$
experts and combination weights. Expert parallel systems can execute this
mapping efficiently when weights are resident and load is balanced. Under
offload or dynamic placement, however, the decision arrives after the system
could have started moving weights.

Reactive histories provide a useful prior but assume future requests resemble
recent requests. Agent execution can shift systematically between planning,
editing, testing, and error recovery. This motivates conditioning expert demand
on request context as well as temporal state.

\subsection{Information boundary}

The useful information must exist before routing. Valid features include
orchestrator metadata and the prompt already admitted to the model. Invalid
features include the current action being generated, target reference answers,
current hidden states, and the current request's router output. This timing
boundary distinguishes a deployable prior from retrospective explanation.
